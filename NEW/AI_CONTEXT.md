# Контекст для AI: fullscreen target lock

Цей документ описує поточну реалізацію тестового fullscreen/web-виводу, lock цілі та збільшеного віконця. Використовуй його разом із кодом — код є джерелом істини, якщо документ і реалізація розходяться.

## Мета

У повноекранному відео показуються рамки підтверджених об'єктів, FPS і кількість збігів (`MATCHES`). Користувач може зафіксувати авто з найвищою впевненістю; окреме збільшене віконце показує detection із найвищою впевненістю.

Це експериментальна комп'ютерно-зоровa функція для тестування. Це не гарантує безперервне стеження за ціллю в будь-яких умовах і поки що не передає команди чи координати через MAVLink.

## Файли та відповідальність

### `NEW/target_lock.py`

Містить клас `TargetLock`, який зберігає стан lock, наближено стежить за вибраною ціллю між кадрами AI та малює всю графіку зафіксованої цілі:

- `enabled` визначає, чи дозволено встановлювати lock.
- `_target` зберігає вибрану detection-структуру, зокрема клас, confidence, рамку та `track_id`.
- `_box` — поточна рамка, яка оновлюється оптичним потоком.
- `_previous_gray` і `_points` — попередній grayscale-кадр і Shi–Tomasi точки всередині рамки.
- `toggle(detections)` знімає активний lock або фіксує detection із найвищим confidence.
- `cycle(detections)` перемикає активний lock на наступну підтверджену ціль із BoT-SORT `track_id`, упорядковану за ID; після останньої переходить до першої. Об'єкти без ID і candidate-об'єкти не включаються.
- `set_enabled(False)` вимикає функцію та скидає активну ціль.
- `update(frame, detections, detection_version)` виконується на кадрах відео:
  - обчислює grayscale;
  - знаходить Shi–Tomasi точки у внутрішній частині рамки;
  - відстежує їх між кадрами алгоритмом Lucas–Kanade (`calcOpticalFlowPyrLK`);
  - зсуває рамку на медіанне переміщення успішно відстежених точок між AI-оновленнями;
  - на новому AI-результаті, якщо optical flow не спрацював, використовує рамку detection того самого BoT-SORT ID;
  - періодично поновлює точки, якщо їх стало мало;
  - коли з'являється новий результат AI, знаходить ту саму ціль за `track_id` і оновлює клас/confidence.
- `draw_locked_overlay()` малює червону рамку, підпис, лінію-вказівник і збільшений crop саме lock-цілі.
- `draw_inset()` відповідає за спільну геометрію, підпис і crop inset; без lock fullscreen-вивід передає сюди detection із найбільшим confidence.
- Лінія проведена від найближчого краю червоної рамки до краю inset, має темний контур для контрасту й не малюється, якщо ціль перекриває inset.
- Якщо рамка повністю виходить за межі відеокадру, lock автоматично скидається. Частково обрізана рамка лишається активною, а новий AI detection того самого ID може скоригувати оптичний дрейф до перевірки меж.
- Кадр не конвертується в grayscale, якщо lock неактивний; це уникає непотрібної роботи в основному циклі.
- Якщо `track_id` відсутній, пошук відповідника обмежений тим самим класом і найближчим центром.

Оптичний потік тут моделює тільки перенесення рамки (translation); масштаб і поворот об'єкта ним не оцінюються. Коротка втрата точок, перекриття об'єкта, вихід із кадру, схожі сусідні машини чи різка зміна ракурсу можуть зірвати або погіршити lock. Це не окремий довготривалий re-identification алгоритм.

### `files/pipeline.py`

Інтегрує `TargetLock` у наявний pipeline:

- створює `self._target_lock = TargetLock()`;
- оновлює lock на кожному новому відеокадрі, передаючи кадр, актуальні detections і версію AI-результату;
- додає стан lock до статистики, яку отримує overlay;
- передає поточну рамку lock у `Overlay.draw`;
- скидає lock при restart джерела;
- `toggle_target_lock()` перемикає Q: якщо lock активний — знімає; інакше вибирає detection із найвищою впевненістю;
- `cycle_target_lock()` перемикає W на наступну confirmed detection із track ID, тільки коли lock активний і є актуальний AI результат;
- перед новим lock перевіряє, що AI увімкнено, є detections і результат належить поточному поколінню джерела; результат не стає недійсним лише через те, що inference триває понад секунду;
- `set_target_lock_enabled()` використовується тумблером T; вимкнення скидає ціль.

Lock працює на відеокадрах, навіть коли новий результат AI ще не надійшов: це дає Lucas–Kanade змогу рухати рамку між повільнішими inference-кадрами. Нові AI detections при цьому допомагають підтвердити ID й освіжити метадані.

### `files/overlay.py`

Малює загальні detection-рамки й HUD, а lock-графіку делегує `TargetLock`:

- існуючі detection рамки лишаються зеленими;
- у fullscreen/minimal HUD рядок містить `FPS`, `MATCHES` і стан `LOCK READY`, `LOCK OFF` або ID активного lock;
- без lock fullscreen-вікно запитує у `TargetLock` inset для detection із найбільшим confidence.

Звичайний web dashboard показує рамки на серверному MJPEG-відео. Гарячі клавіші обробляються `static/app.js`; клавіші Q/T/F перевіряються за фізичним `KeyboardEvent.code`, тому працюють незалежно від активної мовної розкладки.

Fullscreen/minimal HUD вмикається в `pipeline.py` для `VIDEO_OUTPUT` зі значенням `vtx` або `both`. Звичайний web dashboard використовує звичайний overlay і не вмикає це fullscreen-віконце.

### `main.py`

У циклі OpenCV fullscreen-вікна читає клавіші через `cv2.waitKey(1)`:

- **Q/q** — зафіксувати останній доступний detection із найвищим confidence або зняти поточний lock; регістр клавіші підтримується;
- **W/w** — перемкнути активний lock на наступну підтверджену ціль за BoT-SORT ID, циклічно; потрібні щонайменше дві цілі з ID;
- **T/t** — увімкнути/вимкнути target lock; вимкнення також знімає поточну ціль;
- **Esc** — закрити fullscreen-вікно.

У браузері `static/app.js` надсилає ті самі lock-команди в API; Q/W/T/F керуються за фізичними клавішами, а кнопки залишаються альтернативою. W циклічно вибирає наступний confirmed track ID при активному lock. Звичайні поля вводу й селект не перехоплюють гарячі клавіші.

Режим `vtx` тут означає локальне fullscreen-вікно OpenCV. Сам по собі цей режим не є MAVLink-виводом.

## Керування та тестовий запуск

У PowerShell із кореня репозиторію:

```powershell
$env:VIDEO_SOURCE = "file"
$env:VIDEO_OUTPUT = "vtx"
python main.py
```

Це запускає fullscreen pipeline на локальному відеофайлі. Для перевірки lock потрібні видимі detection-об'єкти з активного checkpoint і валідні track ID. Якщо запис результату не потрібний, його можна вимкнути тільки для конкретного запуску:

```powershell
python -c "import config; config.SAVE_OUTPUT_VIDEO = False; import main; main.main()"
```

## Перевірки

### `NEW/visual_approach.py`

Після lock оцінює дистанцію з ширини рамки (pinhole: \(Z = f W / w\)) і з площі (\(Z = Z_0 \sqrt{A_0 / A}\)), потім PID по осі forward формує `SET_POSITION_TARGET_LOCAL_NED` velocity-only setpoint у `MAV_FRAME_BODY_NED`. Утримання — нульова швидкість у межах `APPROACH_HOLD_DEADBAND_M`. Канал 8 — hold-тумблер: ON lock + політ у ціль, OFF unlock + стіки. `MAVLINK_APPROACH_TX` вимикає лише автопілот.

Unit-тести лежать у `tests/test_target_lock.py` та `tests/test_visual_approach.py`; запуск із кореня:

```powershell
.\.venv\Scripts\python.exe -m unittest discover -s tests -v
```

Тести перевіряють:

- вибір highest-confidence detection і toggle lock;
- скидання lock при вимкненні;
- рух рамки Lucas–Kanade на синтетичному зміщенні кадру.

## Важливо для подальшої роботи

- Не прибирай наявні API/поведінку BoT-SORT заради lock: lock є додатковим шаром поверх підтверджених detections.
- Lock вибирає detection із найбільшим confidence; у цій базовій версії клавіші для циклічного перемикання цілей немає.
- Zoom inset незалежно від lock показує detection із найбільшим confidence.
- `ApproachCommander` шле команди лише поки lock активний, лінк живий і (за замовчуванням) armed; втрата lock має залишати нульову швидкість і відновлювати режим. `TargetLock` сам по собі не є failsafe автопілота.
- Зберігай локальні зміни користувача та не перезаписуй їх під час подальших змін.
