# Структура проєкту Drone AI

Цей файл коротко описує призначення каталогів і основних файлів репозиторію. Для поточної поведінки програми джерелом істини є код; документація може відставати від реалізації.

## Як влаштований застосунок

Основний потік кадрів:

1. `main.py` запускає застосунок і створює `PipelineController`.
2. Джерело відео з `files/video.py` або `files/browser_video.py` передає кадри в pipeline.
3. `files/pipeline.py` координує окрему AI-обробку, трекер, target lock, накладку й за налаштуваннями MAVLink.
4. `files/overlay.py` малює рамки та HUD; кадр показується у VTX-вікні або вебінтерфейсі.

## Файли в корені

- `main.py` — основна точка запуску. Створює й запускає pipeline, запускає VTX-вікно, вебінтерфейс або обидва виводи; обробляє клавіші Q/W/T для lock, наступної цілі та стану target lock.
- `main_vtx.py` — старіший окремий VTX-прототип. Має власну організацію процесів і залежить від модулів на кшталт `Config` та `ai_engine`; це не основна точка запуску сучасного pipeline.
- `config.py` — конфігурація джерела й виходу відео, Raspberry Pi профілю, моделі, AI, трекера, відображення, MAVLink, RC-каналів і алгоритмів наведення.
- `requirements.txt` — Python-залежності застосунку.
- `README.md` — загальний опис, запуск, конфігурація й перенесення на Raspberry Pi.
- `PROJECT_GUIDE_UA.md` — український посібник щодо lock, каналів і логіки наведення/передачі команд.
- `PROMPT_INTEGRATION_RPI_UA.txt` — промт-інструкція для Copilot щодо інтеграції функціоналу в окремий робочий проєкт Raspberry Pi.
- `.gitignore` — правила Git для локального середовища, кешів і згенерованих відео/моделей.

## Каталог `files/` — застосункова логіка

- `pipeline.py` — головний координатор кадрів, AI worker, трекера, кандидатів, lock, overlay і MAVLink-циклу.
- `video.py` — джерело відео з файлу або Picamera2; читає кадри у фоновому потоці.
- `browser_video.py` — приймає кадри браузерної вебкамери та надає їх pipeline.
- `ai.py` — обгортка YOLO: завантаження моделі, детекція та повторна перевірка crop.
- `tracker.py` — адаптер до BoT-SORT, що повертає виявлення з track ID.
- `botsort.yaml` — параметри трекера BoT-SORT.
- `candidate.py` — веде слабкі AI-кандидати, вибирає області для повторної перевірки й підтверджує їх між кадрами.
- `overlay.py` — малює рамки, підписи, FPS/HUD і графіку lock-цілі.
- `web.py` — Flask-маршрути сторінки, статусу, відео, керування та передачі кадрів із браузера.
- `utils.py` — невеликі спільні утиліти, зокрема лічильник FPS.

## Каталог `NEW/` — lock і візуальне наведення

- `target_lock.py` — стан вибраної цілі, перемикання на наступний трек та продовження рамки між AI-оновленнями за допомогою оптичного потоку; також малює збільшений inset lock-цілі.
- `visual_approach.py` — обчислення координат цілі у кадрі, оцінки дистанції та setpoint-даних для підльоту/утримання; сам по собі цей модуль не є транспортом MAVLink.
- `AI_CONTEXT.md` — контекст для AI-помічника щодо реалізації lock; звіряй твердження з поточним кодом, якщо описи розходяться.
- `__init__.py` — маркер Python-пакета.

## Каталог `mavlink/` — телеметрія та транспорт команд

- `telemetry.py` — створює MAVLink-з’єднання, читає heartbeat, RC-канали й інші телеметричні повідомлення; також містить методи для відправлення MAVLink-повідомлень, які може використовувати командний модуль.
- `approach_tx.py` — `ApproachCommander`: обирає режим керування, перевіряє умови активності та передає сформовані команди через телеметричний транспорт; підтримує гілки `acro` і `guided`.
- `README.md` — опис налаштувань, каналу lock/cycle та телеметрійного з’єднання.
- `__init__.py` — маркер Python-пакета.

## Каталог `fix/` — PID і ACRO-контролер

- `fix_acro_control.py` — перетворює помилку положення цілі у кадрі й пов’язані дані на нормалізовані команди осей/газу для ACRO-керування; містить обмеження, згладжування та опційні компенсації.
- `fix_pid.py` — PID-регулятор, який використовує ACRO/FIX-контролер.
- `__init__.py` — маркер Python-пакета.

## Вебінтерфейс

- `templates/index.html` — HTML-структура dashboard.
- `static/app.js` — клієнтська логіка dashboard: відео, статус, кнопки та клавіатурне керування.
- `static/style.css` — стилі dashboard.

## Моделі й дані

- `models/best.pt` — custom YOLO checkpoint для звичайного запуску.
- `models/best_ncnn_model/` — NCNN export моделі для Raspberry Pi; містить `metadata.yaml`, `model.ncnn.param`, `model.ncnn.bin` і Python-обгортку `model_ncnn.py`.
- `models/yolo26n.pt` — інша модель, збережена в репозиторії як baseline.
- `models/.gitkeep` — зберігає порожній каталог моделей у Git.
- `input/` — локальні відео для тестування; `test.mp4` і `1test.mp4` є вхідними прикладами.
- `input/.gitkeep` — зберігає каталог у Git, навіть якщо локальні відео відсутні.
- `output/` — вихідні відео та runtime-конфігурації, створені під час роботи.
- `output/botsort_runtime.yaml` — конфігурація трекера, яку застосунок готує для runtime.
- `output/tracked.mp4` — збережений результат обробки відео; це згенерований артефакт, не вихідний код.
- `output/.gitkeep` — зберігає каталог output у Git.

## Тести

- `tests/test_target_lock.py` — unit-тести lock, перемикання цілей, RC-каналів у pipeline та маршрутів керування.
- `tests/test_visual_approach.py` — тести геометрії кадру, оцінки дистанції та розрахунків візуального підльоту.
- `tests/test_approach_tx.py` — тести взаємодії командного модуля з фіктивним MAVLink-транспортом.
- `tests/test_fix_acro.py` — тести PID та перетворення помилки кадру на ACRO-команди.
- `tests/test_mavlink_telemetry.py` — тести розбору телеметрії та значень RC-каналів на фіктивних повідомленнях.

Тести використовують підставні дані/транспорт і не є польовою перевіркою на Raspberry Pi чи реальному польотному контролері.

## Локальні або згенеровані каталоги

- `.venv/` — локальне Python-оточення; створюється на конкретній машині й не є частиною застосункового коду.
- `__pycache__/` та вкладені `__pycache__/` — кеш Python-компіляції.
- `.git/` — внутрішні дані Git-репозиторію; не редагувати вручну.

Ці каталоги можуть бути відсутні на іншому комп’ютері; зазвичай їх не копіюють як частину вихідного коду проєкту.
